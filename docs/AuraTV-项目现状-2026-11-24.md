| 项 | 值 |

| Docker | 29.4.1，Storage Driver = overlayfs，Root Dir = `/opt/docker` |
| 部署内容 | `bitxeno/atvloadly:latest`（v0.8.6） |
| 访问地址 | `http://192.168.5.1:5533`（157 实测 HTTP 200） |
| 数据目录 | `/opt/atvloadly`（容器内挂 `/data`），磁盘剩余约 603MB |
| 自恢复 | `restart=always` |
| 依赖服务 | 宿主机 `dbus` + `avahi-daemon`（opkg 安装，已 enable） |

镜像不是从 Docker Hub 拉的，而是 `docker save bitxeno/atvloadly:latest | gzip -1 | ssh root@192.168.5.1 'gunzip | docker load'`，578MB / 18 秒。原先跑在 157 上的同名容器已停止，避免双实例。

网络侧只加了两处，其余未动：

1. uci firewall rule：放行 `lan → tcp/5533`。
2. uci forwarding：`src=lan dest=docker`（否则 `-p 5533:80` 只做 DNAT、被 fw4 forward 策略丢弃）。

**踩过的严重事故**：安装 `avahi-dbus-daemon` 后它抢占 `0.0.0.0:5353`，而路由器自建 DNS 代理 `oxidns` 也在 5353，导致 dnsmasq 上游全部超时、全屋 UDP DNS 中断。现由用户改为 oxidns 监听 5354、dnsmasq 上游指向 `127.0.0.1#5354`。**今后动路由器任何新服务前，必须先 `netstat -lnup` 核对端口归属。**

**产物门禁（防“CI 绿但装上就崩”）**：

```bash
APP="build/Release-appletvos/AuraTV.app"
test -d "$APP/Frameworks/AMSMB2.framework" || exit 1
PlistBuddy -c "Print :NSBonjourServices" "$APP/Info.plist" || exit 1
PlistBuddy -c "Print :CFBundleShortVersionString" "$APP/Info.plist" || exit 1
```

这组检查是补上来的：首版 IPA 缺 `AMSMB2.framework`（主二进制只留 undefined 引用），装到真机会在 dyld 阶段直接崩，而流水线当时是全绿的。

## 四、本轮修掉的 7 类问题（复现方式与解法）

| # | 现象 | 根因 | 解法 |
| :--- | :--- | :--- | :--- |
| 1 | CI 第一步就失败 `Version "26.04" of Ubuntu is not supported` | `ubuntu-latest` 已升 26.04，`setup-swift@v2` 不认 | `runs-on: ubuntu-24.04` + 用预装 Swift，删掉该 action |
| 2 | `instance method 'lock' is unavailable from asynchronous contexts` | Swift 6 把 `NSLock.lock/unlock` 标为 noasync | 状态改 `OSAllocatedUnfairLock<State>` + `withLock` |
| 3 | IPA 里 `NSBonjourServices` 为空 | `INFOPLIST_KEY_` 前缀机制不支持数组 | 改用 XcodeGen `info.properties` 生成 Info.plist |
| 4 | IPA 缺 `AMSMB2.framework`，真机 dyld 崩 | SPM 的 dynamic product 需显式 embedding | 依赖加 `embed: true`，并在 CI 加存在性门禁 |
| 5 | `AVPlayerItemAccessLog has no member 'lastEvent'` | API 名写错 | 改 `events.last` |
| 6 | `AVDisplayCriteria` 参数不匹配 | 只有 `(refreshRate:formatDescription:)` | 探测时保留 `CMFormatDescription` 一并传入 |
| 7 | 三个 store 调用报 `ActorIsolatedCall` | `AppSettingsStore` 等是 `actor` | `AppEnvironment` 全 async：`bootstrap()` + 所有写操作 `await` |

另有两处 tvOS 不支持的 API 需注意：`.textSelection(.enabled)` 与带坐标的 `onTapGesture` 在 tvOS 上不可用，已分别删除与改为按钮。

GitHub 授权方面：推送 `.github/workflows/` 需要 token 带 `workflow` scope；device flow 轮询间隔低于 12 秒会触发 `slow_down`，且不能多路并发查询同一 device code。

## 五、未完成清单（按严重程度）

1. **解码核**（阻塞级）：当前用 AVPlayer。tvOS 的 AVPlayer 不支持 Matroska(MKV) 容器、DTS/TrueHD 音频、部分 AV1。文档要求的“MKV 蓝光原盘全格式”不成立。KSPlayer 已链接并嵌入，但 `KSEngineAdapter` 未实现。
2. **真机验证**（全部为“未验证”）：装机、启动、SMB/WebDAV 浏览、字幕加载、长按实时出画、HDR/DV 点亮与 24Hz 切换、内存峰值、超长中日文显示。
3. **Apple TV 配对与侧载**：需在电视前操作（设置 → 遥控器与设备 → 遥控器 App 与设备 → 网页扫码 → PIN），无法远程完成。
4. **`AVPlayerEngineAdapter` 的长按策略**：用“暂停 + 近似 seek”实现画面跟随，理论上 >6fps，未实测。
5. **Phase 4**：`MPVEngineAdapter`（备核）、9 项真机验收表未执行。
